# 把时钟旁那一行做成小宇宙

最适合这位主人的小组件，**不靠联网，靠本地计算**。在现有"北京时间"那一行下面加农历与节气（如"九月十七 · 霜降"），旁边加北京的日出日落和月相，状态行下面加一句手写、带日期的近况，再放一只默认不出门、可以叫出来的猫。这几样都不向第三方发请求，不需要 key，大陆访客能否看到只取决于 github.io 本身。两个圈子的小组件文化差别很大。中文博客圈的小组件长在 Hexo 卡片主题上（Butterfly 8,374★，以及由它衍生、走"Heo 风"的 AnZhiYu、Solitude）。主题**内置**的多是网站资讯、运行天数、公告、音乐胶囊、一言打字机这类朴素卡片；大家印象里"可爱"的 IP 欢迎卡、电子钟天气、日历、倒计时、页脚鱼塘，**大多来自社区魔改教程**，不是主题自带。国外独立站圈（Neocities、32-Bit Cafe 一系）看重的是"主人此刻在场"和"访客之间互相来往"：status.cafe 心情、imood、Last.fm 正在听、留言簿、webring、88x31 按钮，以及会追鼠标的 oneko 猫。最脆弱的恰恰是最"中国特色"的公共接口：本次实测，不蒜子计数返回 502，三个公共 Meting 音乐 API 只有一个能用，免费 IP 定位不是 429 就是 403，和风天气的网页插件已经停服。品味上，带着主人真实痕迹、不打扰人、能关掉的组件显得可爱；点击烟花、看板娘、自动播放音乐、满屏粒子和访客计数器，放在学者排版里显得廉价。

> **核实口径**：✅ 表示 2026-10-26 从境外（美国出口代理）实测返回 200，且该功能已在主题 config、README 或页面 HTML 中确认；⚠️ 表示站点在线，但功能细节只来自搜索摘要或记忆，未打开一手页面；❓ 表示本环境代理拦截（CONNECT 502），状态未知，**不等于服务已死**；❌ 表示已停服、404、超时或返回错误。**"大陆可达"一栏全部未在中国大陆实测**：给出的判断来自 GreatFire 对根域名的测试、官方文档或作者自述。"同源"指资源和本站一起由 github.io 提供，可达性与本站相同（GreatFire 2026-10-11 测得 github.io 33% 受干扰）。工作量和维护成本是笔者的估计。

## 中文主题圈：内置卡片朴素，"可爱"全靠魔改

中文博客小组件的源头是 Hexo 卡片式主题。按 2026-10-26 的 GitHub star 数，Butterfly 8,374、Fluid 8,167、Hugo Stack 6,482、NexT 2,782、AnZhiYu 2,551、Volantis 2,219、Stellar 2,063、Redefine 1,972、Solitude 1,187 ([Butterfly](https://github.com/jerryc127/hexo-theme-butterfly))。npm 月下载量 NexT 13,774 居首、Butterfly 10,832 次之 ([npm](https://api.npmjs.org/downloads/point/last-month/hexo-theme-butterfly))。不过很多人用 git clone 安装主题，npm 数会低估实际使用量。Butterfly 的侧边栏 `aside` 提供作者卡、公告、最新文章、最新评论、分类、标签云、归档、系列文章和"网站资讯"卡。网站资讯卡显示文章数、最后更新和"本站已运行 X 天"。访问量交给不蒜子，文档自己承认这个服务"偶尔不稳定"。打字机副标题可以接一言、一句或今日诗词 ([Butterfly 文档](https://butterfly.js.org/posts/4aa8abbe/))。真正让小组件文化繁荣的，是 `inject.head` / `inject.bottom` 这个"注入任意 HTML"的入口：所有魔改都从这里进来。

2023 年以后的"Heo 风"把博客做成了一个**有生活感的个人 App**。AnZhiYu 的默认配置里有正反两面、悬停翻转的公众号二维码卡，作者卡上可以挂表情状态和一组技能标签，`greetingBox` 按时段换问候语（"早上好鸭👋""11点多啦, 在坚持一下就吃饭啦～"）。页脚有"上班 / 下班"状态徽章。此外还有左下角的音乐胶囊、中控台、评论弹幕、右键菜单、深色模式下的星空 canvas，以及切走标签页时标题变成"w(ﾟДﾟ)w 不要走！再看看嘛！"的 `diytitle` ([AnZhiYu _config.yml](https://raw.githubusercontent.com/anzhiyu-c/hexo-theme-anzhiyu/main/_config.yml))。Solitude 的对应功能是 `my_card.state` 时段状态、`witty_words` 随机俏皮话、音乐胶囊、说说页 `brevity`，以及离开页面时把标题改成"404 Not Found"的 `lure` ([Solitude _config.yml](https://raw.githubusercontent.com/everfu/hexo-theme-solitude/main/_config.yml))。克制的一端是 NexT（阅读进度条、书签、GitHub 角标）和 Hugo Stack（只有归档和搜索），Stellar 则把 GitHub 仓库、Issues、Memos、RSS 做成"动态时间线"组件。Stellar 文档明确提醒：这些组件要求浏览器能访问对应 API，**而且对方允许跨域** ([Stellar widgets](https://xaoxuu.com/wiki/stellar/guides/widgets/))。

用户点名的那批"可爱"组件，在 AnZhiYu 默认 config 里**都 grep 不到**。IP 欢迎卡、日历 / 农历、倒计时、年进度条都来自魔改教程 ([AnZhiYu _config.yml](https://raw.githubusercontent.com/anzhiyu-c/hexo-theme-anzhiyu/main/_config.yml))。套路几乎一样：在 `layout/includes/widget/` 下新建 `card_xxx.pug`，外层套主题的 `.card-widget` 样式，数据要么用 JS 本地计算，要么在前端调第三方 API。2026 年 5 月一篇 Butterfly 教程就是这样做访客 IP 卡的，卡片白底、圆角 8px、悬停上浮 2px ([琅琊散记](https://www.langya.org.cn/tech/welcome-ip/))。这套结构可以一对一映射成 Jekyll 的 `_includes/*.html` 加 `assets/js/`。

## 国外独立站圈：卖的是"主人此刻在场"与互相来往

Neocities 一系复兴的不是动画，而是**社交痕迹**。status.cafe 让每人发一条"表情 + 短句 + 多久以前"的近况。它的嵌入脚本先用 `document.writeln` 写出一个 div，再去取 `status.cafe/users/USER/status.json`，返回 `{"author","content","face","timeAgo"}`。所以静态站完全可以自己取这个 JSON、自己写样式，或者在构建时拉取 ([status.cafe current-status.js](https://status.cafe/current-status.js?name=sorbecci))。cinni.net 是这类站点的标本，页面上挤满了小玩意：自定颜色的 imood 心情 GIF、Furcadia 游戏在线状态图、piclog、成排的 88x31 按钮、smartgb 留言簿、Petz 虚拟宠物页和一个主题切换器 ([cinni.net](https://cinni.net/))。webring 则是纯链接：Hotline Webring 只需要两个 `<a>` 指向 `/SLUG/next` 和 `/SLUG/previous`，不用一行 JS ([hotlinewebring.club](https://hotlinewebring.club))。An IndieWeb Webring 从 2024-06-15 起会"自我修剪"，自动标出不活跃的成员 ([xn--sr8hvo.ws](https://xn--sr8hvo.ws))。留言簿依旧被怀念：32-Bit Cafe 的成员用 Atabook、smartgb、Bravenet 或自写表单，垃圾留言靠手工审核；也有人说个人留言簿是在"大家都跑去 Facebook"之后衰落的 ([32-Bit Cafe](https://discourse.32bit.cafe/t/do-you-have-a-guestbook-on-your-website/2280))。

两个细节说明了这个圈子的分寸。其一，sadgrl.online 和 cinni.net 这两个旗舰站都改用 GoatCounter 这种不显示数字的隐私统计（`gc.zgo.at/count.js`），**可见的计数器正在退化成复古装饰** ([sadgrl.online](https://sadgrl.online))。其二，melonking.net 每逢周一显示"Closed Today! C u Tomorrow!"，给网站定了营业时间。它的魅力来自行为本身，而不是装饰 ([melonking.net](https://melonking.net/))。宠物类里，oneko.js 是"a hacky script I wrote to put a cat on my site"：MIT 许可，约 1.3k★，脚本 6,929 字节，源码会检查 `prefers-reduced-motion` ([oneko.js](https://github.com/adryd325/oneko.js), [源码](https://raw.githubusercontent.com/adryd325/oneko.js/main/oneko.js))。较新的 oneko.dhrv.pw 在减少动效时会显示"Your cat is resting"，触屏上点一下空白处，猫就走过去 ([oneko.dhrv.pw](https://oneko.dhrv.pw/))。HN 上对 oneko 只有怀旧和喜爱，唯一的抱怨是它不如桌面版：鼠标停下时，桌面版的猫会挠痒、打哈欠、睡觉 ([HN](https://news.ycombinator.com/item?id=32641192))。iframe 类组件有一个硬伤：样式无法继承宿主 CSS，只能用十六进制颜色和 web-safe 字体，背景透明 ([petrapixel](https://petrapixel.neocities.org/coding/widgets))，放进有深浅色的精心排版里几乎一定会显得突兀。

## 数据源按稳定性分三档：本地计算、可跨域的公共 API、需要 key 或后端

**第一档是纯本地计算，这是静态站的甜区。** 浏览器原生的 `Intl.DateTimeFormat("zh-CN-u-ca-chinese", {timeZone:"Asia/Shanghai"})` 不用任何库就能给出"2026丙午年九月十七星期一"，`formatToParts` 还能拆出干支年名；但它**不提供节气和节日**（Node v22 本地实测，各浏览器尚未逐一测试，微信内置浏览器和旧版 Safari 都没测）。节气、节日、黄历宜忌要用 6tail 的 lunar-javascript：MIT 许可，npm 月下载约 19.2 万，代价是 UMD 包 **113 KB gzip** 且未压缩 ([lunar-javascript](https://github.com/6tail/lunar-javascript), [npm](https://registry.npmjs.org/lunar-javascript/latest))。本地实测 2026-10-26 的输出是"九月十七 丙午马"，上一个节气为 2026-10-23 霜降，下一个为 2026-11-07 立冬。日出日落和月相用 SunCalc 1.9.0，仅 **3.3 KB gzip**，BSD-2 许可。北京当天日出 06:36、日落 17:22，月面照亮 0.998，与 sunrise-sunset.org 的结果相差一两分钟，所以不需要调 API。要注意 SunCalc 2.x 已改为 `index.js`，**没有 `suncalc.js` 了** ([npm suncalc](https://registry.npmjs.org/suncalc/latest))。调休安排是这一档里唯一需要外部数据的，但 MIT 许可的 holiday-cn 每年发布一个 JSON，并注明了国务院通知出处，每年放进 `_data/` 一次即可 ([holiday-cn](https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/LICENSE))。诗句也可以完全本地化：chinese-poetry 采用 MIT 许可，约 5.5 万首唐诗、26 万首宋诗，但唐诗是**繁体**，需要用 OpenCC 在构建时转换 ([chinese-poetry](https://github.com/chinese-poetry/chinese-poetry))。

**第二档是免 key、允许跨域的公共 API，能用，但要设超时和兜底。** 一言 `v1.hitokoto.cn` 实测返回 200 且 `ACAO: *`。一份笔记读到的文档写明国内线路 **2 QPS**、海外线路 20 QPS，属公益服务，高流量站点不先授权可能被临时拉黑 ([一言文档](https://developer.hitokoto.cn/sentence/))；另一次抓取时文档页返回 503，所以这组限额以文档当时的写法为准。今日诗词限每个 IP 每 5 秒 25 次，仅限非盈利使用。它会"**临时获取用户公开的 IP 数据用以推荐**"，并在浏览器里存 token，隐私责任由接入方承担 ([今日诗词文档](https://www.jinrishici.com/doc/))。Bangumi `api.bgm.tv` 的公开收藏接口允许跨域 (`ACAO: *`)，是这一档里最"中文社区友好"的趣味数据；对比之下，B 站接口返回 403 且没有 CORS 头，不能从前端调用 ([Bangumi API](https://api.bgm.tv/v0/subjects/12))。GitHub 贡献日历可以走 jogruber 的接口（限流 10 次 / 10 秒），对 csxq0605 实测返回过去一年 1,319 次贡献 ([jogruber API](https://github-contributions-api.jogruber.de/v4/csxq0605?y=last))。访问量方面，不蒜子的脚本还能下载，计数接口却返回 502 或超时；替代品 Vercount 兼容不蒜子的 span 标签，自称"国内直接访问"，但运营费用由作者一人承担 ([Vercount README](https://raw.githubusercontent.com/EvanNotFound/vercount/main/README.md))。天气上，Open-Meteo 免 key、`ACAO: *`，免费额度是**每 IP 每天少于 1 万次**，数据采用 CC BY 4.0、仅限非商业使用，大陆可达性没有任何一手报告 ([Open-Meteo terms](https://open-meteo.com/en/terms))。

**第三档是需要 key、需要后端，或者对方不允许跨域的服务，纯静态站不该在运行时直连。** 和风天气的网页插件据官方页面已于 **2024-05-01 停止服务**（本环境打不开原页，只看到搜索摘要）([widget.qweather.com](https://widget.qweather.com/en/))；它的旧公共 API 主机返回"Invalid Host"，现在需要按账号分配的主机加 key。彩云天气文档里公开的示例 token 实测已"API quota is exhausted"，正好说明写在前端的 key 会被别人耗光。Last.fm 不带 `api_key` 会返回错误 6。免费 IP 定位里，ipapi.co 返回 429，api.ip.sb 返回 403；ip-api.com 的免费版**只支持 HTTP**，在 HTTPS 的 github.io 上会被当作混合内容拦截 ([ip-api legal](https://ip-api.com/docs/legal))。腾讯位置服务的响应不带 CORS 头，只能走 JSONP，key 必然暴露在页面里 ([meuicat 教程](https://meuicat.com/blog/57/index.html))。这一档的通用解法是 GitHub Actions 定时抓取，把结果写成 JSON 后同源提供：key 留在 secrets 里，访客浏览器不接触任何第三方。代价是：定时任务最短间隔 5 分钟，整点前后常被延迟甚至丢弃，**公开仓库 60 天没有活动会被自动停用** ([GitHub Docs](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/events-that-trigger-workflows))。

## 大陆可达、隐私与维护：同源是唯一可靠的答案

GreatFire 对根域名的测试划出了清楚的边界：**goodreads.com（2026-09-20）和 steamcommunity.com（2026-10-23）100% 封锁**，**raw.githubusercontent.com 100% 受干扰（2026-09-26）**，duolingo.com 被重定向到中国站，neocities.org 和 spotify.com 各 50% 受干扰，github.io 33%，last.fm 9%。letterboxd.com、strava.com、unpkg.com、cdnjs 和 Google Fonts 显示未被封锁；cdn.jsdelivr.net 的最后一次测试停在 2026-07-17 ([GreatFire raw.githubusercontent.com](https://en.greatfire.org/raw.githubusercontent.com), [github.io](https://en.greatfire.org/github.io), [steamcommunity.com](https://en.greatfire.org/steamcommunity.com))。status.cafe、imood、Atabook、GoatCounter 的 gc.zgo.at 在 GreatFire 上**都没有数据**，这只说明没人测过，不说明可达。GreatFire 也只测根域名，测不到 API 子域名和延迟。jsDelivr 在 2021 年 12 月失去中国 ICP 备案，2022 年中出现过 DNS 污染 ([springdoc 论坛](https://forum.springdoc.cn/t/topic/4657))。一个侧证是：AnZhiYu 默认提供 Staticfile、BootCDN 等国内 CDN 选项，Volantis 把不蒜子换成镜像地址 ([AnZhiYu 文档](https://docs.anheyu.com/global/extra.html), [Volantis config](https://raw.githubusercontent.com/volantis-x/hexo-theme-volantis/master/_config.yml))。

**这直接关系到本站已有的世界地图。** `_includes/explore/world.html` 把访客数据地址写成 `https://raw.githubusercontent.com/{{ site.repository }}/visitor-stats/visitor-atlas.json`。按上面的 GreatFire 数据，统计开启后，大陆访客很可能只看得到足迹，拿不到访客层。修法是让 Actions 把 JSON 发布到 Pages 实际提供的同源路径。可选做法有两种：把文件提交到默认分支，每次会触发一次 Jekyll 重建；或者把 Pages 改成由 Actions 部署。这是笔者根据仓库代码和 GreatFire 数据作出的推论，没有实测。同一个模式也是后面推荐里所有"构建时数据"组件的地基。

隐私上有两类组件要特别小心。第一类是**任何 IP 定位问候**：它会把每位访客的 IP 发给境外第三方，而且没有征得同意，在 PIPL 和 GDPR 的语境下都站不住。更好的零网络替代是读 `Intl.DateTimeFormat().resolvedOptions().timeZone` 和 `navigator.language`，再按访客本地时间说"早上好"。大陆访客几乎都是 `Asia/Shanghai` 和 `zh-CN`，这一点是常识推断，没有实测。第二类是**会顺带收集访客数据的"无害"服务**：今日诗词会读访客 IP 并存 token ([今日诗词文档](https://www.jinrishici.com/doc/))；live2d-widget 自己的 README 都警告，默认台词"可能不适合所有年龄段，或不宜在工作期间访问" ([live2d-widget README](https://raw.githubusercontent.com/stevenjoezhang/live2d-widget/master/README.md))。维护成本的规律很简单：中文主题自己的配置注释就在抱怨不稳定，Fluid 说不蒜子"有时不稳定"，Volantis 说 Meting"API经常不稳定" ([Fluid config](https://raw.githubusercontent.com/fluid-dev/hexo-theme-fluid/master/_config.yml))。越依赖第三方实时接口，维护越像是在养一个随时会坏的东西；本地计算的组件写一次，就能一直用下去。

## 可爱与廉价的分界：主人的痕迹，还是通用的特效

没有人系统地调查过哪些组件可爱、哪些廉价，下面的判断综合了社区语气、主题作者的注释和笔者的推断。两个圈子其实给出了同一条分界线：**能带出主人真实痕迹或真实时空的，显得可爱；与主人无关、谁都能贴上去的，显得廉价。** status.cafe 的一句近况、Furcadia 的在线灯、melonking 的周一闭店、AnZhiYu 的"上班 / 下班"徽章、北京此刻的月相，之所以讨喜，是因为它们只属于这一个人、这一个地方、这一刻。点击冒出"富强 民主"、樱花飘落、`canvas_nest` 连线粒子、打字时屏幕震动，属于 2018–2021 年博客园和 CSDN"美化合集"的那一代 ([博客园样式备份](https://www.cnblogs.com/qq2806933146xiaobai/p/15897808.html))，谁的站都能贴，所以显得廉价。第二条线是**是否打扰**。oneko 受到喜爱，部分原因是它在减少动效模式下会"睡觉"；可见的访客计数器、跑马灯、闪图墙、自动播放的音乐，以及不认深色模式的 iframe，都在抢读者的注意力。第三条线是**是否会过期**。"正在读"一行如果两年没更新，读起来就像网站被遗弃了；中文圈的说说页和朋友圈也有同样的问题，而且还要多维护一个后端。

把这三条线套到一个纸白配石板蓝、左栏资料、右栏正文的学者排版上，可爱的一端是：一行文字、等宽小字、只用主题色、可以关掉，信息量高于装饰性。例如农历节气、日出日落、月相、手写近况、年进度细线、按日轮换的一句诗、默认睡着的猫。中间地带是标题卖萌和时段问候：零依赖、零成本，但"w(ﾟДﾟ)w 不要走"这种语气放在英文学者主页上会显得幼稚，要用就改成克制的一句。廉价的一端是：看板娘、点击特效、粒子背景、音乐胶囊、可见的访客数字、IP 欢迎卡，以及 GitHub 贡献热力图这类"晒工作量"的卡片。最后一项不廉价，但主人明确不喜欢围绕项目做文章，绿色格子正好是那种东西。

**第一名是农历与节气副行。** 本站时钟已经在用 `Intl.DateTimeFormat` 加 `Asia/Shanghai`，农历只要再加一个 `zh-CN-u-ca-chinese` 的 formatter，零字节新依赖。节气不要为了一行字在每页加载 113 KB 的 lunar-javascript，可以写一个本地脚本，每年用它算出 24 个节气的日期，存进 `_data/solar_terms.yml`，由 Liquid 和几行 JS 判断"当前节气 / 下一节气"。它把"北京"从一个地名变成一段正在流动的时间，最能体现中文身份，而且和上一份调研提出的"节气强调色"可以共用这张表。要补测 `Intl` 中国历在微信内置浏览器里是否可用，不可用就隐藏这一行。

**第二名是日出日落加月相。** 这对一位力学背景的主人很合适：它是天体力学算出来的，不是从接口拉来的。SunCalc 1.9.0 只有 3.3 KB，北京当天的结果和 sunrise-sunset.org 相差一两分钟 ([npm suncalc](https://registry.npmjs.org/suncalc/latest))。锁定 1.9.0 并自托管，避开 2.x 换掉 `suncalc.js` 路径的坑。月相可以用单个字符或一个 12px 的 SVG 圆，颜色取石板蓝，深色模式下自动反相。如果只想要月相，按 29.53 天朔望月从一个已知新月推算即可，连库都不用。

**第三名是手写近况。** 它借 status.cafe 的形态（表情 + 不超过 60 字 + 多久以前），但数据放在仓库里，不依赖一个 GreatFire 上没有数据的服务 ([status.cafe](https://status.cafe/))。和"Open to internships"放在一起，左栏就同时回答了"他现在想要什么"和"他现在在忙什么"。必须加一条过期保护：超过 60 天没更新就自动隐藏，否则它会变成被遗弃的标志。

**第四名是可召唤的 oneko。** 主人喜欢小组件，宠物是这批推荐里唯一"活的"东西。但学者排版不该让猫一直在正文上跑，所以默认待在页脚，点爪印才出门，选择存在 `localStorage`（读写包在 try/catch 里）；`prefers-reduced-motion` 下猫只睡觉。脚本自托管（unpkg 上没有这个包），**精灵图最好自己画一张石板蓝的**：原 oneko.gif 来自 1980 年代的 Neko 程序，它的版权状态和 MIT 脚本是两回事，本次没有核实 ([oneko.js LICENSE](https://raw.githubusercontent.com/adryd325/oneko.js/main/LICENSE))。不要和 npm 上同名、1.79 MB 的 `oneko` 包混淆。

**第五到第七名是安静的点缀。** 年进度只是页脚的一条细线加一个百分比，零成本；学期或春节倒计时可以以后接 holiday-cn。按日轮换的诗用 day-of-year 取模，全站每天一致，不用 API，也就没有一言的频率限制和今日诗词的 IP 收集问题。chinese-poetry 的诗本身属于公有领域，MIT 只要求保留版权声明 ([LICENSE](https://raw.githubusercontent.com/chinese-poetry/chinese-poetry/master/LICENSE))。落沙或生命游戏作为 Explore 的第四张小卡，和"A little mechanics"的阻尼振子同属一个气质：颗粒物质堆积、元胞自动机，都是力学和智能科学的交叉点。它是玩具，不是项目展示，正合"喜欢小组件、不喜欢围绕项目做花样"的口味。

**第八名是构建时天气，有条件才做。** 时钟旁加上"12°C, clear"，"北京"就更具体了。但它必须走 Actions 抓取、同源发布：Open-Meteo 免 key，数据要标注 CC BY 4.0 署名 ([Open-Meteo terms](https://open-meteo.com/en/terms))。定时任务会在整点前后延迟，公开仓库 60 天无活动会被停用。所以只有先把世界地图的数据通路改成同源以后，再顺带加上天气，才划算。

**明确不推荐的有：**IP 欢迎卡（隐私问题，key 暴露，免费源限流）；音乐胶囊（公共 Meting 三个里挂了两个）；不蒜子；看板娘；点击特效和粒子背景；GitHub 贡献热力图（与主人口味相悖）；Goodreads 和 Steam 的运行时卡片（大陆 100% 封锁）。标题卖萌和时段问候属于"可以但要改写"：如果做，就用一句英文的"Back so soon?"，不用颜文字。

## Conclusion

这次调研让"小组件"这个概念换了一个中心：它的灵魂不在卡片的数量，而在**一个人的时空坐标**。中文圈的魔改和国外的独立站，看似审美相反，一个精致、一个复古，却都在做同一件事：让访客感到"这里有人，此刻在北京，此刻在忙这个"。对纯静态站来说，最好的消息是：这种在场感几乎都可以在浏览器里**算出来**。农历、节气、日月、进度，都是确定的天文与历法，不需要信任任何会停服、限流、被墙的接口。

还没解决的问题集中在测量上。所有大陆可达性都没有实测；`Intl` 中国历在微信内置浏览器里的表现、github.io 在大陆的真实加载耗时、世界地图访客层在大陆是否真的失效，都应该用国内拨测工具或请国内朋友打开确认一次，再决定是否引入任何运行时第三方请求。在此之前，最稳妥的原则只有一条：**能算的不去拉，要拉的放在构建时，放出来的都同源。**
